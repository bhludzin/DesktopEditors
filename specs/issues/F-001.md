# F-001: Pair kerning from a:rPr/@kern was never applied

## What differs

Euro-Office ignored the kern attribute, so text that PowerPoint kerns (kern="1200" on nearly every run of the test deck) was set without kerning. Lines came out wider and broke a word early on about 355 slides.

## What PowerPoint does

Kerning applies when kern > 0 and the font size is at least kern/100 pt. Measured with a COM-built test deck (harness decks kern-rules-A/B): no kern anywhere in the style chain means no kerning (despite the spec text); kern="0" means none; kern equal to the size kerns; kern="1801" at 18 pt does not.

## What Euro-Office does

common/Shapes/Serialize.js skipped rPr attribute 8 (kern); the text model had no kern property; HarfBuzz kerning stayed off because the shaper never set the kerning feature bit.

## Suspected cause

Missing property.

## Where to look

word/Editor/Styles.js CTextPr (Kern, IsKerned, binary extension block flagged by the Ligatures byte high bit); common/Shapes/Serialize.js and SerializeWriter.js (rPr attribute 8); word/Editor/Paragraph/TextShaper.js GetLigaturesType / IsEqualTextPr.
