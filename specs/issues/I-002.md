# I-002: A paragraph that holds only a space run (no endParaRPr) gets its line height from the 18 pt default paragraph mark instead of from the run

| | |
|---|---|
| Status | open |
| Severity | major |
| Slides | 6 |
| Findings | 6 |
| Categories | text-line-spacing |
| Confidence in the cause | high |

## What differs

Six text boxes contain a 'blank' spacer paragraph written as <a:p><a:r><a:rPr sz="1350"/><a:t> </a:t></a:r></a:p>, with no endParaRPr. Euro-Office makes that line 24.0 px tall instead of 18.0 px. Every line below it moves down exactly 6.0 px (PDF: 'Stem of Jesse' baseline 268.92 pt in PowerPoint, 274.31 pt in Euro-Office, +5.39 pt = 1.2 x (18 - 13.5) pt). On slides 6 and 723 the text then overhangs or misaligns with the spAutoFit box. Control cases render correctly: an empty paragraph with endParaRPr sz=1350 (slides 661, 723), and the same box on slide 7 where the paragraph holds real text.

## What PowerPoint does

A line that contains only whitespace takes its height from the runs on it, here the 13.5 pt space run, so the line is 1.2 x 13.5 pt = 16.2 pt (18.0 px). The paragraph-end properties are not used when the paragraph has runs.

## What Euro-Office does

The line has no text (PRS.TextOnLine false) and is the paragraph's last line, so its metrics come from the paragraph-end text properties. With no endParaRPr these fall back to presentation defaultTextStyle lvl1 sz=1800 (18 pt), which makes a 21.6 pt (24.0 px) line.

## Suspected cause

Paragraph.private_RecalculateLineMetrics treats a whitespace-only last line like an empty paragraph: spaces do not update the line metrics (ParaRun.Recalculate_LineMetrics only counts text items), and the condition (PRS.End && !PRS.TextOnLine) forces useParaEnd = true. The run-based fallback that already exists for non-final lines is skipped.

## Where to look

sdkjs/word/Editor/Paragraph_Recalculate.js: Paragraph.prototype.private_RecalculateLineMetrics (1256). See the condition at 1276 and the 'if (true !== PRS.End)' last-run branch at 1279-1311 vs the GetParaEndCompiledPr() branch at 1313-1330. Spaces are not counted in ParaRun.prototype.Recalculate_LineMetrics (word/Editor/Run.js 5051).

## Fix idea

For slide text (!this.bFromDocument), when the last line has no text but its range contains a non-empty run (spaces) before para_End, take the metrics from that run (lastRun.getTextMetrics(true), or the max over the space runs on the line), as the non-final-line branch already does. Use GetParaEndCompiledPr() only when the paragraph has no run content at all. A simpler alternative: let para_Space update the line metrics in presentation paragraphs.
