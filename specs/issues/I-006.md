# I-006: Theme per-script fonts (a:font script="Hebr" -> Arial) are dropped, so the Hebrew run on slide 674 falls back from Calibri: the Hebrew is garbled and the Latin text on that line switches to a fallback font

| | |

| Slides | 1 |
| Findings | 2 |
| Categories | font, other |
| Confidence in the cause | low |

## What differs

Slide 674, Rectangle 5: the line holding a he-IL run is drawn differently in Euro-Office. ' is: ' and '“Hurry to the' are in a narrower sans fallback font, and the line ends 8 px early. The Hebrew is in a typeface other than Arial, and the he-IL hyphen is thinner. Line 2, which belongs to the same en-US run, matches within 0.25 px, so only the line that contains the RTL run is affected. Reviewers also saw the Hebrew letters garbled (logical order, wrong letters, niqqud lost), which suggests the bidi path is involved. One finding.

## What PowerPoint does

Draws the he-IL run with the theme minor font's script="Hebr" typeface (Arial; the cs typeface is empty), and draws the Latin runs on the line in Calibri (+mn-lt) like the rest of the paragraph.

## What Euro-Office does

Has no Hebr script font, because FontCollection keeps only latin/ea/cs, and cs is empty. The Hebrew falls back to a substituted system font. On that line the surrounding Latin text is drawn in a fallback font as well.

## Suspected cause

BinaryPPTYLoader.ReadFontCollection (Serialize.js 5269) skips record 3, the theme's supplemental <a:font script=...> list (5296-5300). FontCollection (Format.js 9984) holds only latin/ea/cs. The he-IL run has an empty +mn-cs, so FontScheme.checkFont (10129-10139) resolves it to +mn-lt (Calibri, which has no Hebrew glyphs) instead of the Hebr script font (Arial). The Hebrew is then shaped and drawn through glyph fallback (logical order, wrong cluster mapping, lost niqqud; the EO PDF embeds only Calibri on this page). The fallback segment apparently also captures the neighbouring Latin text on that line (' is: ', '“Hurry to the'). That spill is not yet confirmed to disappear once the Hebrew resolves to Arial.

## Where to look

sdkjs/common/Drawings/Format/Format.js: FontCollection (9984, only latin/ea/cs) and FontScheme.checkFont (10129); Latin font switch not located (candidates: common/libfont/textshaper.js CTextShaper.private_CheckNewSegment 141-193; word/Editor/Paragraph/draw/content-draw-state.js handleBidiFlow 140)

## Fix idea

Keep the supplemental <a:font script typeface> list of major/minor fonts in FontCollection (loader and PPTY record), and resolve the cs slot for runs whose lang or script is Hebrew (Hebr), Arabic (Arab) and so on to that typeface before falling back to substitution. Then trace slide 674 to find why ' is:' and '“Hurry to the' get a different font id only on the RTL line: log the grapheme font ids from HB_ShapeString and the font that handleText uses.

## Also covers

- Hebrew run ignores the theme's Hebr script font (Arial), falls back from Calibri and comes out garbled (code: sdkjs common/Shapes/Serialize.js: ReadFontCollection (line 5269; case 3 skipped at 5296-5300); common/Drawings/Format/Format.js: FontCollection (9984) and FontScheme.checkFont (10129-10139, falls back to +mn-lt). Bidi ordering is in word/Editor/Paragraph/bidi-flow.js (BidiFlow). The glyph-fallback/shaping path was not located.)
