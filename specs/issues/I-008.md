# I-008: When no line join is specified (in a:ln or the theme line style), Euro-Office strokes with a miter join; PowerPoint uses a round join

| | |
|---|---|
| Status | open |
| Severity | minor |
| Slides | 18 |
| Findings | 18 |
| Categories | shape-fill-line |
| Confidence in the cause | high |

## What differs

18 findings on 18 slides (187-193, 201-206, 243, 585, 676, 679, 701). Affects every outline whose a:ln and referenced theme lnStyleLst entry have no <a:round/>, <a:bevel/> or <a:miter/>. theme1 has no join in any line style, and the only explicit join anywhere in the slide XML is <a:miter/> (189 occurrences). On rectangles it shows as square, filled outer corners where PowerPoint draws an arc of radius w/2: the thick red 3 pt and 4.5 pt frames on 187-193 (1.7-2.5 sheet px radius), and the 1.5-3 pt frames on 243 and 585 (trivial); see crop grouping/work-outlines/0188-corner.png. On acute vertices it shows as miter spikes. The yellow leftArrow heads (1.5 pt) on 201-206 get back-corner spikes about 1 px further out, and the tip moves 0.5 px. The rtTriangle with a 4.5 pt line on 676/679 gets a tip 2.5-4 px beyond PowerPoint's rounded corner. Each of the eleven foldedCorner fold vertices on 701 (2 pt, 31-degree angle) gets a 2.5 px barb. Line widths and positions match.

## What PowerPoint does

An unspecified join is drawn round: its PDF writes '1 j' before every such stroke (re-checked on pages 86, 188, 191, 201, 213, 622, 633 and 701), for rect, line, arc, leftArrow, leftRightArrow, ellipse, custGeom, foldedCorner and rtTriangle. Where the XML says <a:miter/>, PowerPoint writes no 'j' (PDF default miter; e.g. slide 141). One observed exception: prst=rightArrow is stroked with the default miter (no 'j') both rotated (slide 207, rot=19641036) and unrotated (slide 701). Its a:ln (w=19050, solidFill tx1) and lnRef idx=2 are identical to the leftArrow on slide 201, which gets '1 j'.

## What Euro-Office does

Always strokes with a miter join, limit 10: across all 838 pages its PDF contains 2839 join operators and every one is '0 j' (written as '0 J 0 j 10 M'). On screen, the canvas default lineJoin 'miter' applies whenever CLn.Join is null.

## Suspected cause

There are two layers. (1) CShape.recalculatePen never supplies a default Join after merging the theme lnRef style and spPr.ln. ShapeDrawer changes the join only when this.Ln.Join is set, so a null join falls through to the canvas or PDF default (miter). (2) The PDF path cannot write any join at all. fromShape sets OldLineJoin only when 'this.Graphics.m_oContext != null && this.Ln.Join != null'. The PDF renderer (CDocumentRenderer in common/Drawings/Metafile.js, built on CGraphicsBase) has no m_oContext, so OldLineJoin stays null and drawFillStroke's PDF branch never calls put_PenLineJoin, not even for an explicit join. The halves disagreed here: part 2 described the PDF behaviour only for null joins, but the code shows it holds for every join. This deck cannot show the difference because its only explicit join is miter. ConvertJoinAggType already returns round (2) for an unknown type, but that code is never reached for PDF.

## Where to look

sdkjs word/Drawing/ShapeDrawer.js: CShapeDrawer.fromShape (lines 1451-1452: OldLineJoin is set only when m_oContext and Ln.Join.type exist); CShapeDrawer.ds (lines 2202-2226: canvas lineJoin switch); CShapeDrawer.drawFillStroke, PDF branch (lines 2287-2289: put_PenLineJoin). Pen compiled in common/Drawings/Format/Shape.js: CShape.prototype.recalculatePen (3121). Join conversion: common/Drawings/Format/Format.js: ConvertJoinAggType (7562). PDF renderer: common/Drawings/Metafile.js: CDocumentRenderer (3105) and its put_PenLineJoin (3373).

## Fix idea

Both changes are needed, or the PDF output stays mitered. (a) In CShape.prototype.recalculatePen, after pen.merge, if this.pen.Join is null (or its type is null), set it to a LineJoin of type AscFormat.LineJoinType.Round (or treat null as Round inside ShapeDrawer). (b) In ShapeDrawer, decouple the PDF path from m_oContext: compute joinType in fromShape regardless of the graphics object, save and restore m_oContext.lineJoin only when a context exists, and in drawFillStroke's PDF branch always call this.Graphics.put_PenLineJoin(AscFormat.ConvertJoinAggType(joinType)), plus the miter limit when a:miter lim is given. Afterwards check: slide 188 (round frame corners); slides 201, 676, 679 and 701 (spikes gone); slide 141 (explicit miter stays miter); and the rightArrow on 207 and 701, which PowerPoint miters and may need a preset-specific exception.
