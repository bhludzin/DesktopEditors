# I-012: Picture (p:pic) outlines are stroked centred on the picture edge (and twice) instead of entirely outside it

| | |
|---|---|
| Status | fixed (fixed in sdkjs 555e9eabe3 (fix(slide): draw picture outlines outside the picture)) |
| Severity | minor |
| Slides | 7 |
| Findings | 7 |
| Categories | picture, shape-fill-line |
| Confidence in the cause | high |

## What differs

Every picture with an outline is affected (7 slides: 228, 430, 431, 622, 693, 694, 702; 6 findings). PowerPoint draws the frame outside the image. Euro-Office centres it on the image bounds, so the frame sits w/2 further in on every side and its inner half covers the outer w/2 of the image. With a 3 pt border (slide 622) the frame is 1.5-2 sheet px inside PowerPoint's: a red ring outside and a blue ring inside in the difference map, with about 1.7 px of the image hidden. With the 0.75 pt frames (228, 430, 431, 693, 694) the frame is 0.4-0.8 px inside. Those frames also have no w, so outlines/1's 1 pt fallback makes them 3 px thick at the same time; these pictures need both fixes. The 0.15 pt frame (w=1905) on 430/431 shows the same inward shift as a one-column offset. Euro-Office also strokes each picture outline twice, once in the spPr pass and again in the blip pass; the PDFs of pages 622 and 702 show two identical strokes.

## What PowerPoint does

Strokes the outline path on the picture rectangle inflated by w/2 on every side, so the inner edge of the line lies on the image boundary. PDF slide 622: image x 355.78 w 268.31, outline '354.28 262.87 271.31 202.13 re' with 3 w (1.5 pt outward on each side). Slide 693: image x 390.0, outline 389.62 w 306.28 = image + 0.75 (0.375 pt outward). Slide 228: 141.13 vs 141.50, width 421.75 = 421.00 + 0.75.

## What Euro-Office does

Strokes the outline on the picture's own calcGeometry, centred on the boundary: on PDF page 622 the path origin is 355.78125 and the width 268.31251, with '2.99999 w', which is the image rect itself. The inner half of the line covers the image, and the stroke is emitted twice ('S' in both draw passes, the second after the image fill).

## Suspected cause

CImageShape.prototype.draw calls ShapeDrawer.fromShape2/draw with this.calcGeometry and this.pen twice: once with the spPr brush and once with the blip brush. The pen is never moved outward for pictures. A commented-out `this.pen.w *= 2` in CImageShape.recalculatePen shows the problem was noticed before.

## Where to look

sdkjs common/Drawings/Format/Image.js:CImageShape.prototype.draw (line 582; stroke passes at lines 612-613 and 642-643); Image.js:CImageShape.prototype.recalculatePen (line 362)

## Fix idea

In CImageShape.prototype.draw, draw the blip fill with pen = null. Then draw the outline once, in a separate pass, with geometry for the rect inflated by pen.w/2 (EMU/36000 mm): either recompute the geometry for extX + w, extY + w and translate by (-w/2, -w/2) before stroking, or prepend that scale/translate to the transform for the stroke pass only. Drop the pen from the first (spPr brush) pass so the outline is not stroked twice. Leave shapes (p:sp) centred.
