# I-015: Run-level text effects (a:rPr/a:effectLst, e.g. outerShdw text shadow) are dropped on load and never drawn

| | |
|---|---|
| Status | open |
| Severity | minor |
| Slides | 4 |
| Findings | 4 |
| Categories | text-color-effects |
| Confidence in the cause | high |

## What differs

White 13.5 pt quote text over a dark, leafy photo panel (Rectangle 4 on slides 186, 187, 194 and 195; the same runs are on 188-190) has a soft black drop shadow in PowerPoint. The pixels 1, 2 and 4 px below the glyphs have luminance 15, 23 and 33, against about 43 above them. Euro-Office draws no shadow at all: those pixels read 40, 42 and 43. Glyph positions are identical. The effect is subtle on the dark part of the panel and clearly missing over the light foliage, where PowerPoint's letters have a dark underside.

## What PowerPoint does

Draws each run's outerShdw (blurRad 50800 = 4 pt, dist 50800 = 4 pt, dir 5400000 = straight down, colour tx1 black, opaque) behind the glyphs: an offset, Gaussian-blurred copy of the text in the shadow colour.

## What Euro-Office does

Ignores the run's effect list. The text is drawn without the shadow.

## Suspected cause

x2t writes the rPr effect list as record 2 (core/OOXML/PPTXFormat/Logic/RunProperties.h: `pWriter->WriteRecord1(2, EffectList)`), but sdkjs's ReadRunProperties skips record 2 (`case 2: s.SkipRecord();`). CTextPr has no property for text effects, and the paragraph drawing code has no shadow pass.

## Where to look

sdkjs/common/Shapes/Serialize.js: BinaryPPTYLoader.ReadRunProperties, child record `case 2: s.SkipRecord();` (9086); text drawing in sdkjs/word/Editor/Paragraph/draw/content-draw-state.js (handleRun 176 / handleText 303)

## Fix idea

In ReadRunProperties case 2, read the record with the existing this.ReadEffectProperties() (Serialize.js:5568) or ReadEffectLst (5502) and store it on the run properties (for example rPr.EffectLst). Carry it through CTextPr Copy/Merge/IsEqual/Write_ToBinary and the PPTY writer (SerializeWriter.js WriteRunProperties). When drawing a slide paragraph, render outerShdw first: draw the run's glyphs offset by dist along dir in the shadow colour into a temporary layer, blur it by blurRad, then draw the normal text on top. The shape-shadow code in word/Drawing/ShapeDrawer.js can serve as a reference. A cheaper first step is an unblurred offset copy at reduced alpha.

## How to verify

Build and render with `python fidelity/fidelity.py loop <deck> --label <name>`, then rebuild the review facts with `python fidelity/review_prep.py <deck-dir> <name>` and look at the slides below: their findings should be gone, and no other slide should lose line-break matches or SSIM against the previous run (`fidelity.py runs <deck>`). Then set `status` and `fixed_in` in `issues.json`, add a `log` entry, and re-run `review_record.py`.
