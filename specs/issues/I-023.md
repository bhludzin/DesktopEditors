## What differs

Found while fixing I-020, not by the review. On the mixfont-rules test decks Euro-Office's PDF embeds Trebuchet MS for Century Gothic, Times New Roman for Garamond, Palatino Linotype for Book Antiqua, Arial for Arial Narrow and Franklin Gothic Medium for Franklin Gothic Medium Cond, and Gill Sans MT is substituted too; PowerPoint's PDF embeds each of them. All are installed on this PC (C:\Windows\Fonts\GARA.TTF, GOTHIC.TTF, GIL_____.TTF, BKANT.TTF, ARIALN.TTF, FRAMDCN.TTF), and Aptos, the theme font of the test decks' template, is in Office's cloud-font cache (%LOCALAPPDATA%\Microsoft\FontCache\4\CloudFonts). The harness gives x2t m_sAllFontsPath = fidelity-work\runtime\euro-office-9.3.8\converter\AllFonts.js, the list shipped in the portable 9.3.8 package. Its fonts.log shows it was made on the build machine (paths under D:\a\DesktopEditors\DesktopEditors\core-fonts, a GitHub Actions runner) from that machine's C:\Windows\Fonts: 334 font files and none of the Office-installed ones. The desktop app makes its own list at start in %LOCALAPPDATA%\Euro-Office\DesktopEditors\data\fonts (434 files, with all of the above and Aptos), so the app itself is not affected, only harness renders. The 838-slide deck uses only Calibri, Calibri Light and Times New Roman, which both lists have, so its scores are not affected.

## What PowerPoint does

Draws every font installed on the PC, including Office's cloud fonts (Aptos, the default theme font of new Office presentations).

## What Euro-Office does

Before the fix, in harness renders: substituted a font missing from the shipped list, with other widths and vertical metrics (Garamond's first baseline at 18 pt sat 0.81 pt lower than PowerPoint's, as Times New Roman's would). The desktop app was never affected: it makes its own list on this PC at start.

## Suspected cause

Confirmed. x2t gives m_sAllFontsPath to the doctrenderer, where it overrides DoctRenderer.config's allfonts (sdkjs's font list), and the native side (the pptx reader's font picker and the PDF renderer) loads font_selection.bin from m_sFontDir, falling back to x2t's own folder. The harness passed the converter's AllFonts.js and C:\Windows\Fonts, which has no font_selection.bin, so both sides used the lists shipped in the converter, made on the build server.

## Where to look

DesktopEditors fidelity/fidelity.py: pc_font_list (runs x2t -create-allfonts), font_list_meta, render_run (m_sAllFontsPath and m_sFontDir in x2t-params.xml) and the --shipped-fonts option of render and loop.

## Fix idea

Point m_sAllFontsPath at the desktop app's list (%LOCALAPPDATA%\Euro-Office\DesktopEditors\data\fonts\AllFonts.js, next to its font_selection.bin), or make a list for the runtime from this PC's fonts, and record in run.json which list a run used. Rerender the release baseline and the latest run with it so they stay comparable. Then recheck the font cases of mixfont-rules and mixfont-rules2 (Garamond, Century Gothic, Gill Sans MT, Book Antiqua at 48 pt, Arial Narrow) and the four Aptos boxes of mixfont-rules4.

## How to verify

Build and render with `python fidelity/fidelity.py loop <deck> --label <name>`, then rebuild the review facts with `python fidelity/review_prep.py <deck-dir> <name>` and look at the slides below: their findings should be gone, and no other slide should lose line-break matches or SSIM against the previous run (`fidelity.py runs <deck>`). Then set `status` and `fixed_in` in `issues.json`, add a `log` entry, and re-run `review_record.py`.
