## What differs

Found in the desktop app, not by the review or the harness; not a rendering difference but a blocker. Every GUI bundle built from sdkjs f1e24ab652 (K5) to 12b5e8c974 failed to open every deck, a 6-slide one included: after x2t converted the file, the editor showed "An error has occurred while opening the file. Press "OK" to close the editor.", and the console had TypeError: this.Parent.Get_ParentTextTransform is not a function. The stock 9.3.8 release opens the same decks. The PDF harness could not catch it: x2t never draws those thumbnails.

## What PowerPoint does

Opens the deck (not a rendering difference).

## What Euro-Office does

Before the fix: the editor showed the open error for every presentation. Now it opens them: a copy of the 3963-slide deck (great-roll-3963) opens in the GUI in 79-106 s, slides 154, 931, 3335 and 3963 render, edits and Save work, and the saved file reopens with the edits.

## Suspected cause

Cause found: since K5 (sdkjs f1e24ab652) every slide text draw calls Paragraph.GetSlideBaselineInfo, which walks up through CDocumentContent.Get_ParentTextTransform. While a presentation opens, CPresentation.GenerateThumbnails draws the master and layout thumbnails with CMasterThumbnailDrawer, whose "Aa" sample is a CDocumentContent parented to the CPresentation, and CPresentation has no Get_ParentTextTransform, so the draw threw.

## Where to look

sdkjs word/Editor/DocumentContent.js CDocumentContent.Get_ParentTextTransform (now calls the parent's only when it has one); called from word/Editor/Paragraph.js Paragraph.GetSlideBaselineInfo (K5); the thumbnails are drawn by slide/Editor/Format/Presentation.js CPresentation.GenerateThumbnails with slide/Editor/Format/SlideMaster.js CMasterThumbnailDrawer.

## Fix idea

Done (see euro_office).

## Open questions

- Harness gap: nothing in the harness exercises the GUI open path (x2t never draws the master and layout thumbnails), so a change that breaks only the editor goes unseen; this fix was checked by hand.
- Save As was not checked (it needs the native file dialog).

## How to verify

Build and render with `python fidelity/fidelity.py loop <deck> --label <name>`, then rebuild the review facts with `python fidelity/review_prep.py <deck-dir> <name>` and look at the slides below: their findings should be gone, and no other slide should lose line-break matches or SSIM against the previous run (`fidelity.py runs <deck>`).
