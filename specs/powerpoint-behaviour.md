# PowerPoint rendering rules

These are the rules PowerPoint follows, as measured from its PDF export, from test decks built
with PowerPoint itself (COM automation) and from the 838-slide review. Each rule links to the
issue that implements it or still needs it. Where the evidence is thin, the issue's confidence
says so. The numbers come from PowerPoint's PDF unless stated otherwise.

## Implemented in the fork

| Rule | Issue |
|---|---|
| Pair kerning applies when `a:rPr/@kern` > 0 and the font size is at least `kern`/100 pt. If `kern` is missing from the whole style chain there is no kerning (the spec text says otherwise). `kern="0"` means none. A `kern` equal to the size kerns; `kern="1801"` at 18 pt does not. | [F-001](issues/F-001.md) |
| Punctuation and digits (Unicode script Common) are shaped together with the surrounding Latin text, so letter+period and letter+comma pairs are kerned. | [F-002](issues/F-002.md) |
| Text is laid out in whole 1/576-inch units (1/8 pt). Each glyph's own advance is rounded to a whole unit at the run's size (S pt = 8·S units per em, halves up), spaces included, and pair kerning is then added unrounded. Bold and regular follow the same rule. Word start positions in PowerPoint's PDF follow this to within about 0.02 pt per 100 pt at 13.5, 15 and 18 pt regular and 13.5, 24 and 30 pt bold. Exact design widths drift by +0.05 to +0.21 pt per 100 pt (regular) and -0.32 (bold 13.5). Truncating the kerning instead (the first hypothesis) drifts by -0.1 pt per 100 pt. Regular 12.75 pt is the one size that fits less well (about 0.1% long). | [K2](issues/K2.md) |
| A line wraps when it would be wider than the box width minus the insets rounded down to whole 1/576-inch units. This replaces the fitted 0.25 pt reduction of F-003. | [K3](issues/K3.md), [F-003](issues/F-003.md) |
| `a:rPr/@sz` is used exactly, in hundredths of a point (12.75 pt stays 12.75 pt), for advances, glyphs and line pitch. | [I-001](issues/I-001.md) |
| Line ends are filled, never stroked. A triangle head is sm 2×, med 3× or lg 5× the line width (with a floor of about 2 pt) in width and in length. The tip sits exactly on the end point, and the shaft is shortened under the head. | [K1](issues/K1.md) |
| An `a:ln` with no `w` and no `p:style/a:lnRef` is 9525 EMU (0.75 pt) wide. With an `lnRef`, the theme's `lnStyleLst` width applies. | [I-007](issues/I-007.md) |
| Picture outlines are stroked on the picture's rectangle grown by half the line width, so the line lies entirely outside the image. | [I-012](issues/I-012.md) |
| A space sizes its line like text does. A line holding only spaces takes its height from them (a 13.5 pt space makes a 16.2 pt line, whatever `endParaRPr` says), and a larger space on a text line makes that line taller. Empty paragraphs take their height from `endParaRPr`. | [I-002](issues/I-002.md) |
| The gap between paragraphs is the space after the first plus the space before the next: they are added, not collapsed (10 + 10 pt gives 20 pt). Percentage spacing adds the same way. The first paragraph's space before and the last paragraph's space after are not used. | [I-003](issues/I-003.md) |
| Spacing given in points (`spcBef`, `spcAft` and `lnSpc` `spcPts`) is used in whole points, halves up: 4.2 → 4, 4.5 → 5, 0.5 → 1, 2.5 → 3, 13.5 → 14, 20.5 → 21. Percentage spacing is not rounded. | [I-009](issues/I-009.md) |
| Latin text may break at any space, including before `.`, `,`, `;`, `:`, `!`, `?`, `)`, `]`, `%` or a closing quote (`”`, `’`, `»`), so a spaced ellipsis can start a line. Without a space before it, the punctuation stays with its word. | [I-004](issues/I-004.md) |
| Kerning also applies across spaces (space+A, space+T, A+space and so on) in kerned runs, also where a run boundary falls next to the space, as long as the font and size are the same on both sides. | [I-005](issues/I-005.md) |
| Complex-script characters (Hebrew, Arabic, Thai, Indic and so on) use the run's `cs` font. When the theme leaves the `cs` typeface empty, the theme's `a:font script` entry for the run's **language** is used (he-IL → Hebr, ar-SA → Arab), whatever script the letters are in: Arabic letters in a he-IL run use the Hebr font. Spaces and punctuation in such a run use that font too. Hebrew in an en-US run uses Arial for the letters and the Latin font for the spaces. | [I-006](issues/I-006.md) |
| A line may break after an en dash (U+2013), between digits (`8:34–35`, `1850–1851`) as between letters (`slain–army`). The dash stays at the end of the line. | [I-022](issues/I-022.md) |
| Superscripts and subscripts (`a:rPr/@baseline`) are drawn at exactly 2/3 of the run size, with no rounding (13.5 → 9 pt, 12.75 → 8.5 pt). The baseline moves by the stated fraction of the run size: `baseline="30000"` raises 18 pt text by 5.4 pt, `-25000` lowers it by 4.5 pt. | [I-010](issues/I-010.md) |
| A letter followed by a hyphen-minus is not kerned (`T-`, `r-`, `V-`). Pairs with en and em dashes are kerned as usual. | [I-011](issues/I-011.md) |
| In a box with `wrap="none"`, trailing spaces count in the line width for centred and right-aligned lines, on every line, including one that ends at `<a:br/>`. In a wrapped box they do not count, even when the text fits on one line. | [I-013](issues/I-013.md) |
| Underlines and strikethroughs are filled bars sized from the face's own metrics, on a 1/600-inch (0.12 pt) grid counted from the text box. The baseline is rounded down to the grid. The underline's top is `post.underlinePosition` below it and the bar is `post.underlineThickness` thick. The strike's top is OS/2 `yStrikeoutPosition` above it and the bar is `yStrikeoutSize` thick. Each value is scaled to the run size and rounded to whole grid steps. So Calibri Bold strikes, and Times New Roman Bold and Arial Bold underlines, are thicker than regular ones. A strike follows its own run (a superscript's at 2/3 size on its raised baseline), and so does a subscript's underline. A superscript's underline stays on the line's baseline at the full run size. Touching underlines on one baseline become one bar: its top and bottom are the runs' width-weighted means, each rounded. `dblStrike` draws two bars of the strike's thickness, directly above and below the single strike's place. | [K4](issues/K4.md) |
| Under percentage line spacing other than 100%, and under exact spacing, a line is H high: the percentage of the text height (1.2 × the font size; the tallest text on a mixed line) or the exact value in whole points. A quarter of H lies below the baseline, plus however much the font's single-spacing descent exceeds a quarter of the single line height (Courier New). At single height or less, the part below is never more than the font's descent. The rest lies above. So 18 pt Calibri's first baseline is 24.3 pt below the box top at 150% (Word's rule keeps it at 16.85), 12.96 at 80% and 14.69 at 90%. Exactly 100% keeps the font's own ascent, so 101% puts the first baseline about 0.5 pt higher than 100% does. `normAutofit lnSpcReduction` is subtracted from the percentage, also from `lnSpc` set on the paragraph itself (150% − 20% = 130%); exact spacing is not reduced. For `ctr` and `b` anchoring the last line ends at its font descent: the rest of its line height is not counted. Baselines are then snapped to a 1/600-inch grid (up to 0.12 pt). | [I-017](issues/I-017.md) |
| A font's single line (1.2 × its size) is split above and below the baseline at its OS/2 win ascent : win descent (at its typo ascent : descent, with the typo line gap above, when `USE_TYPO_METRICS` is set). The hhea line gap does not count: Times New Roman puts 0.8047 of the line above the baseline (92.70 pt at 96 pt), Calibri 0.78, Arial 0.8103. | [I-016](issues/I-016.md) |
| A line that mixes fonts: each run takes 1.2 × its own size, split at its font's ratio. The `a:br` that ends the line adds its font at the size of the line's last run, and so does the paragraph mark on the last line when the paragraph has an `a:endParaRPr` (even one without a font; with none the mark does not count). Their own sizes do not count, and a bullet's font does not count at all. The line takes the largest part above and the largest part below the baseline, scaled down together to 1.2 × its largest run size. So 18 pt Calibri with an Arial run is no taller than all-Calibri, with the baseline 0.14 pt lower (16.99 instead of 16.85); with Courier New 0.73 pt higher. A smaller run in another font counts at its own size. Line spacing (I-017) then works on these parts. | [I-020](issues/I-020.md) |
| An outline with no join (none in its `a:ln` or in the theme line style its `lnRef` names) is stroked with a round join, on presets, custom geometry, connectors and pictures, except 31 presets that PowerPoint strokes with a miter join even when the join is `<a:round/>`: `bentUpArrow`, `chevron`, `cube`, `downArrow`, `ellipseRibbon`, `ellipseRibbon2`, `leftArrowCallout`, `leftRightArrowCallout`, `leftUpArrow`, `mathEqual`, `mathMinus`, `mathMultiply`, `mathNotEqual`, `mathPlus`, `moon`, `notchedRightArrow`, `plus`, `quadArrowCallout`, `rightArrow`, `star4`, `star5`, `star8`, `star10`, `star12`, `star16`, `star24`, `star32`, `stripedRightArrow`, `upArrow`, `upDownArrow` and `upDownArrowCallout`. `<a:bevel/>` and `<a:miter/>` are used as given on every shape. The miter limit is always 10, whatever `lim` says. | [I-008](issues/I-008.md) |
| Letters that combine with a mark into one glyph (Hebrew bet with dagesh, shin with shin dot) are drawn with the mark. PowerPoint's PDF embeds the composed glyph; Euro-Office's did too, but every font it embedded had a broken `cmap`, so Windows drew the text with system fonts, one character per glyph, and lost the marks. Fixed in core (the PDF writer), not sdkjs. | [I-021](issues/I-021.md) |
| An outer shadow whose `blurRad` is above 0 is a blurred silhouette: the object moved by `dist` at `dir` (scaled by `sx`/`sy` about `algn`; a picture's outline included, since it lies outside the picture), in the shadow colour at its alpha times the fill's, blurred with a Gaussian whose standard deviation is `blurRad` / 3. PowerPoint draws it as an image reaching `blurRad` past the silhouette, at 200 dpi divided by ceil(3 × `blurRad` / 8 pt) (100 dpi at 4 pt, 16.7 dpi at 32 pt). `rotWithShape="1"` turns the direction with the shape. A shadow at distance 0 is not grown: only its blur shows. | [I-014](issues/I-014.md) |
| A line's baseline lies a whole number of 1/600 inch (0.12 pt) below the top of the text, halves rounded down. The top of the text is where the first line starts: the text area's top after `tIns`, moved by the anchoring. The whole distance is rounded, ascent part, space before and line spacing included (Calibri 13.5 pt: first baseline 12.636 → 12.6 pt; 18 pt: 16.848 → 16.8; 12 pt: 11.232 → 11.28). The PDF then stretches text down by 0.1075 pt over the slide's height, about its top edge, and puts it on a 1/3000-inch (0.024 pt) grid from the slide's top. A rotated box is rounded in its own frame and stretched in slide coordinates. On the 838-slide deck 99.1% of lines are on PowerPoint's baseline. Arial 24 pt lands one step higher than PowerPoint's. | [K5](issues/K5.md) |
| A picture is drawn as its image clipped to its shape (`re W* n` … `cm /Image Do`), not as a tiling-pattern fill, and a cropped picture's image holds only the part shown. Every picture is re-encoded, a JPEG too: lossless (Flate) when it has at most 256 colours or JPEG would not make it smaller, otherwise JPEG at quality 75. Transparency (its alpha times `alphaModFix`) is a soft mask with the colour premultiplied by it (`/Matte [0 0 0]`); a blurred shadow's image follows the same rule. Tiled fills stay tiling patterns. Fixed in core (the PDF writer), for presentations only. | [K6](issues/K6.md) |
| PowerPoint's PDF draws text in glyph runs on a 1/3000-inch (0.024 pt) grid. A layout position x (in grid cells from the slide's left edge) is drawn at x × (1 + a) + b, with a = 1.48323e-4 and b = 0.0304 on 720 × 540 pt slides and a = 1.28602e-4 and b = 0.0311 on 960 × 540, so line starts stretch by about 0.12 pt over the slide's width. A run starts at that position rounded to the nearest cell. If the position lies s sixteenths of a cell past it (−8 to 7), each glyph n cells wide adds floor((s + 8 + round(16·n·a)) / 16) cells to everything after it: at s = 7 every glyph at least about 5 pt wide adds 0.024 pt, at s = 6 every glyph at least about 15 pt wide, below that none. The phase is the run's own, not carried from glyph to glyph. So a long line can come out 1.5 pt longer than its layout, and the lines of one paragraph differ. A run restarts at each `a:r` (one of only spaces continues into the next), before and after a hyphen, en dash or em dash, at tabs, pictures and equations, and at each line. Only left, justified and distributed lines get the extra cells, and not a run with character spacing, the run after a dash, or a run after a space in the middle of a line. Left and justified indents are rounded to the nearest 1/600 inch. Line breaks are not affected. Only 720 × 540 and 960 × 540 pt slides are handled. | [I-027](issues/I-027.md) |
| Each glyph of a glyph run (I-027) is drawn where PowerPoint's 600-dpi device and PDF writer put it. Device: whole pixels at ppem = round(size × 600 / 72) pixels per em. A glyph after a space goes to the pixel nearest its layout position from the run's start (an exact half down below 1024 px, up from there); any other glyph follows the one before by that glyph's advance and kerning, each rounded to whole pixels, moved back a pixel while it is more than 3.5 px ahead of its layout position and on a pixel while its end is 5.5 px or more short of the next glyph's layout position. PDF writer: each glyph's PDF width is its advance in 1/1000 em rounded to 1/64 and then to a whole unit, at the PDF font size (K2); it adds up how far the device advances (with I-027's extra cells) run ahead of those widths, and once that reaches 3 units either way moves the next glyph by it less a half, cut towards zero, and drops the rest. So lines come out a little shorter than their layout, by font and size: about 0.27 per mille at Calibri 13.5 pt, 0.5 at 18 pt, 1.3 at 12.75 pt. Spaces before a run's first other glyph are left out of the PDF's text. Not followed: the Tc on lines of one glyph repeated, and the ~4% of word starts a pixel off the nearest. Runs with character spacing and glyphs whose advance is not known (ligatures, fonts emboldened in code) stay at their layout widths. Line breaks are not affected. | [I-024](issues/I-024.md) |

## Not implemented yet

### Text

| Rule | Issue |
|---|---|
| PowerPoint sometimes wraps a word that its 1/576-inch layout fits by up to 0.14 pt (slides 15, 906 and 1308 of the 1646-slide deck, by 0.14, 0.06 and 0.04 pt). Whether it keeps a margin, or measures the line wider, is not known. | [I-028](issues/I-028.md) |
| The PDF's font size is the run size on PowerPoint's 600-dpi device, 5 cells a pixel, stretched down the slide like the baseline (13.5 → 13.56, sometimes 13.584; 12.75 → 12.72; 40 → 39.96). Not reproduced: Euro-Office draws glyphs at the run size, below 0.06 pt different, invisible at the review resolution. Where the glyphs go is reproduced (I-024). | [K2](issues/K2.md) |
| `u="dbl"` and `u="heavy"` underlines (measured once, 24 pt Calibri, in grid steps below the baseline): `dbl` is two bars 10–17 and 29–36 (the single underline is 23–36), and `heavy` is one bar 10–30. Euro-Office draws both as a single underline. The review deck uses neither. | [K4](issues/K4.md) |
| Run-level effects (`a:rPr/a:effectLst`, such as `outerShdw`) are drawn: a blurred, offset copy of the text. | [I-015](issues/I-015.md) |
